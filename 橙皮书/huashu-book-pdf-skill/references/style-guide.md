# 风格指南 · 降 AI 味

> 橙皮书是教程手册，结构化（步骤/表格/代码块）是必要的，但**文字部分必须有个性化语感**，不能写成工具书。

## 核心原则

**作者是真实存在的人，不是知识库复读机。** 读者要感受到：
- 思考过程（不是给结论）
- 个人判断（不是两边都对）
- 经验感（不是理论推演）
- 边界感（不是全知全能）

## 去 AI 腔 Checklist

每章写完后过一遍：

### 1. 排比/对仗
- ❌ 「首先...其次...最后...」「一方面...另一方面...」
- ✅ 直接列，或者讲故事

### 2. 套话开头
- ❌ 「在当今...」「随着...的发展」「众所周知」
- ✅ 直接进场景

### 3. 套话结尾
- ❌ 「总而言之」「综上所述」「希望本文对您有帮助」
- ✅ 给一个具体可操作的下一步，或一个反问

### 4. 过度客观
- ❌ 「这有优点也有缺点...」「具体选择因人而异」
- ✅ 说你的判断，给出条件

### 5. 万能形容词
- ❌ 「非常重要」「极其关键」「巨大的潜力」
- ✅ 用具体数字/事实替代

### 6. 伪思考痕迹
- ❌ 「让我们一起来看看...」「接下来我将为你介绍...」
- ✅ 直接讲，像跟朋友解释

### 7. AI 礼貌语
- ❌ 「请注意」「请确保」「建议您...」
- ✅ 直接说「记住」「注意」「别忘了」

## 加个性化语感

### 写「我」的判断
- ✅ 「我自己的习惯是...」「我试下来发现...」
- ✅ 「坦白讲，这个我一开始也没想明白」
- ✅ 「这一步我吃过亏，告诉你别再踩」

### 写经验感
- ✅ 「跑过 3 个项目后回头看...」
- ✅ 「刚开始我也觉得这个 API 没必要...」
- ❌ 纯理论推演，没有「我」

### 写边界感
- ✅ 「这块我了解不深，下面主要是调研结论，不是亲测」
- ✅ 「这一段花叔在另一个项目里详细讲过，这里就不展开了」
- ❌ 假装什么都懂

### 写思考过程
- ✅ 「一开始我以为是 X，跑通后发现其实是 Y，因为...」
- ✅ 「这里有个反直觉的点：...」
- ❌ 直接给结论

## 标点与排版硬规则

| 项 | 规则 |
|----|------|
| 破折号（——） | 每片段最多 **1 处**，多了视觉很乱 |
| 引号 | 用「」，不用 "" 或 '' |
| 加粗 | 每片段约 **10 处** 标记重点，不要每个词都加粗 |
| 段落长度 | 手机屏 **3-5 行** 为佳，不超 7 行 |
| 句子长度 | **15-25 字** 为主，超 30 字考虑拆 |
| 小标题密度 | 每 **300-500 字** 一个 h3，不密集 |
| 中英文混排 | 中英文之间加空格（`用 Claude 写代码` 而非 `用Claude写代码`） |
| 全角/半角 | 中文段落用全角标点，英文/数字/代码用半角 |

## 反例 vs 正例

### 段首

**反例**：
> 在当今 AI 快速发展的时代，AI Native Coding 已经成为一个非常重要的趋势。本文将为你介绍 Claude Code 的使用方法。

**正例**：
> 上周我用 Claude Code 重构了一个 5 万行的老项目，4 小时搞定。要是你还在手动改 bug，这篇就是写给你的。

### 工具对比

**反例**：
> A 工具和 B 工具各有优势。A 工具更轻量，B 工具功能更全。具体选择取决于用户需求。

**正例**：
> 试了 3 个月 A 工具，最近换回 B 了。A 的轻量是真的，但少了 B 的多文件编辑，写中型项目就是折磨。如果你的项目不超过 1 万行，A 够了；超过这个数，建议直接 B。

### 介绍概念

**反例**：
> 让我们一起来了解一下什么是 Agent Skills。Agent Skills 是一种重要的概念，它可以帮助 AI Agent 更好地完成各种任务。

**正例**：
> Agent Skills 是个有点反直觉的设计——把「工具调用」包装成「能力描述」，让 Agent 自己决定什么时候用。看着像多此一举，但跑复杂任务时，错误率能降一半。

### 给出建议

**反例**：
> 建议读者根据自身情况选择合适的方法。希望本文对您有所帮助。

**正例**：
> 这一步我建议直接抄我的 config，自己摸索要调一周。如果你是「想理解原理」型选手，那就慢慢玩，但别在生产环境用半成品。

## 句式小技巧

### 用「你」而不是「读者/用户」

**反例**：「读者需要先安装 Node.js」
**正例**：「先装个 Node.js（用 LTS 版，别用最新版）」

### 用具体数字代替形容词

**反例**：「非常快」「极其重要」
**正例**：「从 5 秒降到 200ms」「错一行全表崩，这是必须配的项」

### 用对比和反问

**反例**：「应该注意版本兼容」
**正例**：「版本不对，连编译都过不去——别问我怎么知道的」

### 主动暴露自己的选择

**反例**：「可以采用多种方法」
**正例**：「我自己用的是 pnpm，速度比 npm 快 3 倍，monorepo 必备」

## 审校 Checklist（每个审校 agent 必跑）

- [ ] 没有排比/对仗/首先其次最后
- [ ] 没有套话开头和结尾
- [ ] 过度客观的地方加了「我」的判断
- [ ] 万能形容词都换成了具体数字
- [ ] 破折号每片段不超过 1 处
- [ ] 加粗每片段约 10 处
- [ ] 段落长度都在 3-7 行
- [ ] 句子长度大部分在 15-25 字
- [ ] 中英文之间有空格
- [ ] 至少 3 处出现「我」的真实表达

## 一句话心法

> **「如果把『我』全去掉，这段话还是成立的，那它就是 AI 写的。**
> **好的写作，删掉「我」就站不住。」**
