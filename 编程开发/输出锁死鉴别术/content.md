# 输出锁死鉴别术 · 让「看起来没跑、其实在按设计跑」的自动化现形

> 3F Content 范式 · F1 源文字版 · 流水线「输出不变」的根因鉴别

---

## P0 · 封面 / 定位

- **标题**：输出锁死鉴别术
- **副标**：让「看起来没跑、其实在按设计跑」的自动化现形
- **章节类型**：封面 / 定位
- **核心主张**：同一种症状有两种根因——「它坏了」和「它本来就该这样」——方向判错，后面全是白工
- **认知锚点**：「两只一模一样的钟」—— 一只坏了停摆，一只好好走着却永远指向同一个刻度
- **关键要点**：
  - 输出连续三天一字不差，第一反应该是「它坏了」，但更常见的答案是「它一直就是这样」
  - 静态候选池 + 恒假筛选条件 = 名单锁死：管道每一行都在正常跑，只是永远跑到同一个分支
  - 鉴别只需一个动作：**找一个本该变、而且真的在变的东西，做对照**
- **数据 / 数字**：2 种根因 · 4 步鉴别 · 1 个对照量
- **金句**：它没坏，它只是从来没被允许变

---

## P1 · 现象 / 痛点

- **标题**：输出锁死的三种面孔
- **副标**：名单一字不差、日报每天长一样、告警永远只报那几只
- **章节类型**：现象 / 痛点
- **核心主张**：锁死的输出有个共同特征——它**每天都准时出现**，比正常输出还可靠
- **认知锚点**：「三条一模一样的输出流」—— 三条打印出的报表，纸张、格式、墨迹完全一致
- **关键要点**：
  - 面孔一 · 名单锁死：连续 3 天同样 29 只候选、同样 10 只入选，逐字一致
  - 面孔二 · 报告锁死：日报模板写死，每天换的只有日期，结论一字不变
  - 面孔三 · 告警锁死：监控绑的是静态标的清单，规则写得再细也只盯那几只
- **数据 / 数字**：3 天 · 29 只候选 · 10 只入选 · 逐字一致
- **金句**：越稳定的输出，越值得怀疑它被焊死了

---

## P2 · 根因 / 原理

- **标题**：锁死是怎么长出来的
- **副标**：静态池 × 恒假条件 = 必然收敛到同一个结果
- **章节类型**：根因 / 原理
- **核心主张**：锁死不需要任何 bug，只需要两件完全正常的事凑在一起
- **认知锚点**：「一个被焊死的齿轮箱」—— 每个齿轮都在转，但传动比让输出轴永远指向同一个刻度
- **关键要点**：
  - 原理一 · 静态候选池：29 只标的的代码、赛道、评分、逻辑全写死在源码里，管道只能从这 29 只里挑
  - 原理二 · 恒假分支：当日主线 Top5 是陶瓷行业、次新股、酿酒行业、印刷包装、农林牧渔，不含半导体关键词 → `has_relevant_market = False`
  - 原理三 · 强制降级 + 静态排序：条件为假 → 29 只全被压成 B 级 → 按写死的评分取前 10 → 名单必然锁死
- **数据 / 数字**：29 只写死 · Top5 零命中 · 全量降为 B · 恒取前 10
- **金句**：不是算法挑不出新的，是它只被允许在 29 个选项里挑

## P3 · 诊断 / 排除

- **标题**：四步鉴别：先证明它没坏
- **副标**：别在错的根因上改一天
- **章节类型**：诊断 / 排除
- **核心主张**：动手改之前，先用四步证明「锁死」而不是「故障」——判错方向，药就不对症
- **认知锚点**：「四道窄门」—— 四道只能容一人通过的窄门，每道门后通向不同结论
- **关键要点**：
  - 第 1 步 · 逐字对比：把多天的输出文件做 diff——**字节级一致**是「写死」的最强信号，不是「可能」，是「几乎不可能来自动态数据」
  - 第 2 步 · 看上游：管道喂进去的候选池，是不是一张写死的常量表
  - 第 3 步 · trace 分支：跑一次带 trace 的执行，看关键分支是不是永远走同一边
  - 第 4 步 · 查开关名：找有没有「相关性 / 阈值 / 开关」这类变量，被上游条件恒定锁死
- **数据 / 数字**：4 步 · 1 次逐字 diff · 1 条 trace
- **金句**：先证明它没坏，再决定改什么

## P4 · 解法 / 操作

- **标题**：三条修复动作
- **副标**：接活水源、留痕降级、划清边界
- **章节类型**：解法 / 操作
- **核心主张**：锁死不是 bug，不需要修 bug，需要把「它能变的空间」还给它
- **认知锚点**：「重新接上的三根管线」—— 三根被焊死的管道重新接入活水源
- **关键要点**：
  - 修 1 · 候选池接活水源：静态池接动态来源（涨停池 / 资金流 / 板块龙虎榜），工具才能从「筛选器」升级为「发现器」
  - 修 2 · 降级要留痕：降级发生时必须把 reason 写进结果（如「主线脱节」）——否则你永远分不清「没信号」和「没查」
  - 修 3 · 诚实地划边界：写清工具是筛选器还是发现器，别让使用者以为它会扫出新东西
- **数据 / 数字**：3 条修复 · 1 个动态来源 · 1 个 reason 字段
- **金句**：让工具说清楚它今天为什么没找到

## P5 · 进阶 / 纪律

- **标题**：四条纪律
- **副标**：把今天学费变成以后不再交的规矩
- **章节类型**：进阶 / 纪律
- **核心主张**：静态不是罪，锁死才是——把「静态」和「锁死」分开，是这套方法最值钱的地方
- **认知锚点**：「四道护栏」—— 四根立在机器旁的护栏，每根都拦住一种自欺
- **关键要点**：
  - 纪律一 · 静态不是罪：精选池写死往往是对的，问题在于「筛选条件会不会把它全降级」
  - 纪律二 · 先证明再动手：改候选池治不了「筛选条件恒假」这个病——药不对症等于换一种坏
  - 纪律三 · 对照量优先：任何「输出没变」的怀疑，都必须配一个活的对照量（涨停家数 115 → 48）
  - 纪律四 · 诚实标注边界：筛选器不是发现器，工具定位写在文档第一行，别等用户来问
- **数据 / 数字**：4 条纪律 · 1 个对照量 · 115 → 48
- **金句**：先证明它没坏，再相信它没坏

## P6 · 场景 / 迁移

- **标题**：同一个毛病的五个分身
- **副标**：推荐、告警、日报、爬虫、增量同步
- **章节类型**：场景 / 迁移
- **核心主张**：换掉名词，这套鉴别法一字不改地照样成立
- **认知锚点**：「一只虫的五个分身」—— 同一只甲虫戴着五种帽子出现在五个场景里
- **关键要点**：
  - 推荐系统：候选池写死 + 热度排序写死 → 每天推同一批
  - 监控告警：规则绑定静态标的清单 → 告警永远只盯那几只
  - 日报周报：模板与结论写死 → 每天只换日期
  - 爬虫任务：目标 URL 清单写死 → 只抓固定几个页面
  - 增量同步：增量起点写死 → 每轮都从同一处开始
- **数据 / 数字**：5 个场景 · 1 套鉴别法
- **金句**：换个行业名，锁死还是那张熟悉的嘴脸

---

## P7 · 收束 / 速查

- **标题**：速查卡：症状 → 查什么 → 怎么修
- **副标**：一格三栏，贴墙备查
- **章节类型**：收束 / 速查
- **核心主张**：把鉴别顺序固化成肌肉记忆，下次两分钟定性
- **认知锚点**：「口袋速查卡」—— 一张三栏卡片：左边症状，中间动作，右边结论
- **关键要点**：
  - 输出逐字不变 → 查候选池是不是常量表 → 接动态来源
  - 分支恒走一边 → trace 关键条件 → 修条件，不要修排序
  - 全量被降级 → 查降级 reason 有没有留痕 → 补 reason 字段
  - 对照量也在变 → 判定为设计性锁死，不是故障 → 改池不改逻辑
  - 一句话记住：**先证明它没坏，再决定改哪里**
- **数据 / 数字**：4 行症状 · 4 个动作 · 1 条原则
- **金句**：问对问题，锁死自己会解开
