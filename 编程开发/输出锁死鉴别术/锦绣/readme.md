## 公众号版（深度 · 1500-2000 字）

标题：**连续三天输出一模一样，我以为程序坏了，结果它只是从来没被允许变**

你有没有遇到过这种情况：某个自动化工具连着跑了三天，每天准时产出，格式漂亮，日志干净，exit code 全是 0。你随手对比了一下三天的结果——**一字不差**。同样的名单，同样的数量，同样的顺序，连标点都对得上。

第一反应当然是：坏了。缓存没更新？数据源昨天就挂了？定时任务是不是没跑？

于是你花了一个下午排查日志、翻接口、改配置、重跑脚本——**全是白工**。因为它根本没坏。

真实案例：某每日机会扫描工具，连续三天输出**同样 29 只候选、同样 10 只入选**，逐字一致。查下来真相是：候选池是**静态硬编码**的 29 只卡脖子半导体股（代码、赛道、评分、逻辑全写死在源码里），而当天的市场主线 Top5 是陶瓷行业、次新股、酿酒行业、印刷包装、农林牧渔——**一个都不含半导体关键词**。于是 `has_relevant_market` 恒为 False，29 只全被强制降级成 B 级，再按写死的评分取前 10 名。

**名单必然锁死。** 管道每一行都在正常跑，程序没有 bug，它只是永远跑到同一个分支。

### 一、锁死的三种面孔

**面孔一 · 名单锁死。** 连续 3 天同样 29 只候选、同样 10 只入选，逐字一致。

**面孔二 · 报告锁死。** 日报模板写死，每天换的只有日期，结论一字不变。

**面孔三 · 告警锁死。** 监控绑的是静态标的清单，规则写得再细，也只盯那几只。

锁死的输出有个共同特征——它**每天都准时出现**，比正常输出还可靠。这正是它能潜伏很久的原因：它看起来太健康了。

### 二、锁死是怎么长出来的

答案很反直觉：**锁死不需要任何 bug，只需要两件完全正常的事凑在一起。**

**静态候选池。** 29 只标的的代码、赛道、评分、逻辑全写死在源码里。管道能做的，只是在这 29 个选项里挑。

**恒假分支。** 当日主线里没有半导体 → `has_relevant_market = False`。这个条件不是偶尔为假，是**每天为假**。

**强制降级 + 静态排序。** 条件为假 → 29 只全被压成 B 级 → 按写死的评分取前 10。三个正常机制串起来，输出就锁死了。

### 三、四步鉴别：先证明它没坏

动手改之前，先用四步证明「锁死」而不是「故障」。判错方向，药就不对症。

**第 1 步 · 逐字对比。** 把多天的输出文件做 diff。注意，是**字节级一致**——这不是「可能」是写死，而是「几乎不可能来自动态数据」。一旦是逐字一致，静态嫌疑就已经是压倒性的。

**第 2 步 · 看上游。** 管道喂进去的候选池，是不是一张写死的常量表？去源码里找那个列表。

**第 3 步 · trace 分支。** 跑一次带 trace 的执行，看关键分支是不是永远走同一边。如果 `has_relevant_market` 这个变量从来没出现过 True，你已经找到锁扣了。

**第 4 步 · 查开关名。** 找有没有「相关性 / 阈值 / 开关」这类变量，被上游条件恒定锁死。

**外加一个对照量。** 这是最关键的一招：**找一个本该变、而且真的在变的东西做对照**。那个案例里，涨停家数从 115 掉到 48，主线板块每天全变——**行情侧是活的**。如果连对照量都不变，那才是真故障。

### 四、三条修复动作

锁死不是 bug，不需要修 bug，需要把「它能变的空间」还给它。

**修 1 · 候选池接活水源。** 静态池接动态来源（涨停池 / 资金流 / 板块龙虎榜），工具才能从「筛选器」升级为「发现器」。

**修 2 · 降级要留痕。** 降级发生时必须把 reason 写进结果（比如「主线脱节」）。否则你永远分不清「今天没信号」和「今天根本没查」。

**修 3 · 诚实地划边界。** 写清这个工具是筛选器还是发现器。别让使用者以为它会扫出新东西——它做不到。

### 五、四条纪律

1. **静态不是罪，锁死才是。** 精选池写死往往是对的，问题在于「筛选条件会不会把它全降级」。
2. **先证明再动手。** 改候选池治不了「筛选条件恒假」这个病。药不对症，等于换一种坏。
3. **对照量优先。** 任何「输出没变」的怀疑，都必须配一个活的对照量。
4. **诚实标注边界。** 筛选器不是发现器，工具定位写在文档第一行，别等用户来问。

### 六、换掉名词，这套方法一字不改地成立

推荐系统：候选池写死 + 热度排序写死 → 每天推同一批。
监控告警：规则绑定静态标的清单 → 告警永远只盯那几只。
日报周报：模板与结论写死 → 每天只换日期。
爬虫任务：目标 URL 清单写死 → 只抓固定几个页面。
增量同步：增量起点写死 → 每轮都从同一处开始。

> **姊妹篇**：《静默故障排查术》讲的是「怎么发现它坏了」。这一本讲的是「怎么证明它没坏」。两本合起来，才是把「输出不变」这件事查到底。

## 小红书版（精简 · 350 字 + 8 张图）

**连续三天输出一模一样，我以为程序坏了——结果它只是从来没被允许变。**

三种面孔：
① 名单锁死（同样 29 只候选、同样 10 只入选）
② 报告锁死（每天只换日期）
③ 告警锁死（规则再细也只盯那几只）

根因一句话：**静态候选池 × 恒假筛选条件 = 输出必然锁死。**
真实案例：候选池写死 29 只半导体股，当天主线 Top5 是陶瓷/次新股/酿酒/印刷包装/农林牧渔，零含半导体 → `has_relevant_market` 恒 False → 29 只全降 B 级 → 按写死评分取前 10。**名单锁死。**

四步鉴别：
① 逐字 diff（**字节级一致 = 写死的最强信号**）
② 看上游候选池是不是常量表
③ trace 关键分支是不是恒走一边
④ 查开关名被谁恒定锁死

三条修复：
接动态来源（涨停池/资金流/龙虎榜）· 降级必须写 reason · 诚实标注是筛选器还是发现器

**静态不是罪，锁死才是。**
