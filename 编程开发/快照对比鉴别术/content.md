## P0 · 封面 / 定位

- **标题**：快照对比鉴别术
- **章节类型**：封面 / 定位
- **核心主张**：每天自动巡检，第一眼看到的"数字掉了"，**九成不是东西坏了**，是你昨天和今天用了两把不同的尺子
- **认知锚点**：「两把刻度不同的尺子」——一把量出 40，一把量出 37，量的却是同一堆东西
- **关键要点**：
  - 症状不是"少文件"，是**跨轮对比对不上**：昨天 40 个，今天 37 个，字节还差 9.4 MB
  - 最贵的误判是"东西真坏了"：于是开始找备份、找恢复、找历史版本——**动的是数据，全是白工**
  - 真根因只有一句话：**两轮统计的 pattern 不是同一个**（`*讲解.pdf` vs `*.pdf`）
  - 一句话口径：**先对齐口径，再看数字**；用**字节总量相等**当"零丢失"的硬证据
- **数据 / 数字**：3 个差额 · 123,863,174 字节逐字节相等 · 9 类 bucket 逐桶不变
- **金句**：数字掉了不一定是坏了，也可能是你换了尺子

## P1 · 现象 / 痛点

- **标题**：每天早上的第一眼
- **章节类型**：现象 / 痛点
- **核心主张**：自动巡检的全部价值建立在"输出不变"这件事本身就是信号，所以**数字一变，就自动触发"出事了"的警报**
- **认知锚点**：「每天早上的第一眼」——凌晨跑完的脚本，早上第一眼扫过去，数字红了一格
- **关键要点**：
  - 巡检的设计前提是"输出不变 = 系统没动"，所以**任何变化都被默认当成故障**
  - 而变化有三种来源：**东西真变了** / **尺子变了** / **你看错了**——三者的正确处理完全相反
  - 第一种最贵：你按"东西真变了"处理，开始恢复、回滚、找备份，**动的是数据**
  - 第二种最隐蔽：尺子由**你自己**在上一轮悄悄改掉，下一轮自动触发假警报
  - 第三种最阴险：日志被截断，**你拿到的是一份"看起来完整"的错数据**
- **数据 / 数字**：3 种变化来源 · 只有 1 种需要恢复
- **金句**：巡检的红灯不一定是系统坏了，有时候是尺子坏了

## P2 · 根因 / 原理

- **标题**：同一张桌子，量出两个答案
- **章节类型**：根因 / 原理
- **核心主张**：假故障的唯一根因是**口径漂移**——两轮统计的匹配规则、时间窗、归一化方式只要有一个不同，数字必然对不上
- **认知锚点**：「同一张桌子，量出两个答案」——桌子没动，量的人换了刻度
- **关键要点**：
  - 本次实证：11-21 段记的是 `*.pdf`（**含 3 个 legacy 变体** `-v2/-v3/-v4`），今天查的是 `*讲解.pdf`（F3 真正校验的 pattern）→ **40 vs 37 的差额一个不少地对上**
  - 口径三要素必须**三同时同**：① 匹配 pattern ② 时间窗（含边界） ③ 归一化规则（大小写 / 路径前缀 / 排序）
  - 最容易漂的是 **pattern**：人写命令时随手从 `*.pdf` 改成 `*讲解.pdf`，**自己完全不记得**
  - 判定"真丢"还是"换尺子"的关键动作：**把口径退回最宽的全量再比一次**——全量字节 123,863,174 与历史记录**逐字节相等**，一次判定零丢失
  - 教训：**口径不是记录里的细节，是比数字更前置的东西**。先记口径，再记数字
- **数据 / 数字**：3 个 legacy 变体 · 123,863,174 = 123,863,174（差 0 字节）
- **金句**：先问"昨天那把尺子长什么样"，再问"东西是不是少了"

## P3 · 破局 / 手法

- **标题**：先对齐尺子，再看数字
- **章节类型**：破局 / 手法
- **核心主张**：跨轮对比的三件套——**对齐口径 → 用字节总量判生死 → 全量捕获再分类**，按顺序做，跳过任何一步都会得出错误结论
- **认知锚点**：「先对齐尺子，再看数字」——两把尺子并排放，先校准刻度，再读数
- **关键要点**：
  - **第一步 · 对齐口径**：把两轮的匹配 pattern、时间窗、归一化规则写成**同一行**再比；先确认"我这次量的是不是同一堆东西"
  - **第二步 · 字节总量判生死**：文件数会骗人（改名、替换、拆分都可能对不上），**总字节逐字节相等 = 几乎不可能是巧合**——这是"零丢失"最硬的单一证据
  - **第三步 · 全量捕获再分类**：校验脚本的输出**必须全量落盘**再统计；`tail -N` 是分类计数的头号杀手
  - 补一条：**退出码对 ≠ 结果对**。`check-3f` 的 EXIT=0/1 仍然正确，但被截断的 ❌ 详情行会让 bucket 计数全错——**失败的失败方式是"静默错"**
  - 顺序不能换：先对齐口径（否则后面全是噪声）→ 再判生死 → 最后才分类定位
- **数据 / 数字**：3 步 · 9 类 bucket · 退出码与计数是两件事
- **金句**：先对尺子，再读数，最后才拆解

## P4 · 陷阱 / 边界

- **标题**：被掐掉尾巴的日志
- **章节类型**：陷阱 / 边界
- **核心主张**：最贵的假故障不是口径漂移，是**输出被截断后你还拿它做分类统计**——它不报错，只是悄悄算错
- **认知锚点**：「被掐掉尾巴的日志」——屏幕最后一屏没了，但前面几行看起来完全正常
- **关键要点**：
  - 现场：按习惯跑 `check-3f.py <dir> | tail -5`，**每个 case 只留下最后 5 行** → ❌ 详情行（缺 PDF / 缺 images / 页数不一致）全被截掉
  - 后果：EXIT 分布（34 PASS / 53 FAIL）**完全正确**，但 9 类 bucket 计数**全部失真**——因为详情行不在了
  - 更阴险的一层：**截断是"看起来正常的失败"**。你不会收到报错，只会拿到一个偏低的 bucket 数，然后据此下判断
  - 修法（一行）：`> out.txt 2>&1` **全量落盘**，再用 `grep` / `awk` 在**文件**上分类，不要在管道上分类
  - 通用判据：**任何要用来做统计的输出，都不能经过会丢行的管道**；`tail` / `head` / `grep -m` / `sort | head` 都是隐形截断器
- **数据 / 数字**：tail -5 · 87 个 case · 190 条 bucket 明细
- **金句**：管道是给人看的，文件才是给统计用的

## P5 · 零破坏 / 可逆

- **标题**：零破坏对账四步
- **章节类型**：零破坏 / 可逆
- **核心主张**：鉴别"真丢还是换尺子"**不需要碰任何生产数据**——四步全是只读动作
- **认知锚点**：「零破坏对账台」——台子上只有放大镜和尺，没有手术刀
- **关键要点**：
  - **Step 1 · 读口径**：把上轮记录里的统计命令 / pattern 抄下来，与本轮**并排**摆着，差异一眼可见
  - **Step 2 · 退到全量**：用**最宽的 pattern**（如 `*.pdf`）重新统计一遍，与历史总量比**字节**
  - **Step 3 · 分类定位**：全量捕获输出，按 ❌ 真实行解析出各 bucket（**不要 grep 猜数**）
  - **Step 4 · 结论归档**：把"本轮口径"写进记录，**让下一轮有一把可比的尺子**——否则今晚的坑明晚重演
  - 底线：**这一整套动作不改、不删、不恢复任何文件**；确认"没丢"之前不要动数据，确认之后也只是补记录
- **数据 / 数字**：4 步 · 0 次写操作 · 1 条口径留档
- **金句**：鉴别阶段只读，修复阶段才动刀

## P6 · 验证 / 度量

- **标题**：一次判定的三个数
- **章节类型**：验证 / 度量
- **核心主张**：结论必须由**三个数同时成立**才成立，缺一个就下不了结论
- **认知锚点**：「一次判定的三个数」——三块砝码同时落在天平上，才算平
- **关键要点**：
  - **数一 · 口径**：本轮与上轮的 pattern / 时间窗 / 归一化规则**逐条对齐并写下来**（写下来才算数过）
  - **数二 · 字节总量**：全量字节与历史记录**逐字节相等** → 判定"零丢失"（本次 123,863,174 = 123,863,174）
  - **数三 · bucket 分布**：9 类 bucket **逐桶计数不变**（本次 50 / 49 / 47 / 34 / 5 / 2 / 1 / 1 / 1，与上轮完全一致）→ 判定"零回归"
  - 三个数的分工：**数一排除"换尺子" · 数二排除"真丢" · 数三排除"坏了"**
  - 验收标准：**三个数齐了才能说"仓库状态正常"**；缺任何一个，最多只能说"没发现异常"
- **数据 / 数字**：3 个数 · 0 差额 · 9 类 bucket
- **金句**：一个数只能怀疑，三个数才能定案

## P7 · 收束 / 速查

- **标题**：五步落地卡
- **章节类型**：收束 / 速查
- **核心主张**：把这套动作压成 5 行，每天巡检时照着跑
- **认知锚点**：跳过 —— 纯清单，文字讲更清楚
- **关键要点**：
  - **Step 1 · 对齐口径**：上轮 pattern + 时间窗 + 归一化，并排抄下来
  - **Step 2 · 读全量**：校验输出**全量落盘**，不要在管道上统计
  - **Step 3 · 判生死**：最宽 pattern 重算，比**总字节**（不是文件数）
  - **Step 4 · 分类**：按真实 ❌ 行解析 bucket，逐桶与上轮对齐
  - **Step 5 · 留档**：把本轮口径写进记录，让下一轮有尺子可对
  - 三个验收标准：**字节总量相等** ✅ · **bucket 逐桶不变** ✅ · **口径已留档** ✅
  - 一条底线：**没对齐口径之前，不要断言"东西丢了"，更不要动手恢复**
- **数据 / 数字**：5 步 · 3 个验收标准 · 0 次破坏
- **金句**：对口径、比字节、查分类、留口径
