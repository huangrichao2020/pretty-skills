# 静默故障排查术 · 让「看起来在跑、其实没跑」的自动化现形

> 3F Content 范式 · F1 源文字版 · 定时任务 / 数据管线的静默故障排查

---

## P0 · 封面 / 定位

- **标题**：静默故障排查术
- **副标**：让「看起来在跑、其实没跑」的自动化现形
- **章节类型**：封面 / 定位
- **核心主张**：最贵的故障不是报错的那些，是一声不吭跑了好几个月的那些
- **认知锚点**：「哑巴闹钟」—— 一口指针在走的钟，却从不为任何人响
- **关键要点**：
  - 报错会来找你，静默故障不会——它只是安静地替你把数据做旧
  - 定时任务失败、数据停在昨天、标签全错但无报错：三种最常见的面孔
  - 排查的起点不是看日志，而是先问「这个任务到底跑没跑过」
- **数据 / 数字**：4 种面孔 · 4 步分诊 · 4 条修复
- **金句**：它没报错，只是从来没跑过

---

## P1 · 现象 / 痛点

- **标题**：静默故障的四种面孔
- **副标**：脚本日志一片安静，数据停在昨天，标签全错却零报错
- **章节类型**：现象 / 痛点
- **核心主张**：静默故障有一个共同点——它失败在「你看不见的那个地方」
- **认知锚点**：「四张假面孔」—— 四个人戴着笑脸面具，面具底下是空洞
- **关键要点**：
  - 面孔一 · 脚本日志安静：cron 每分钟都在触发，日志里什么都没有
  - 面孔二 · 数据停在昨天：抓取脚本没报错，页面上的日期就是不动
  - 面孔三 · 标签全错：数字都对，逻辑全错——连板序列整体错位一天
  - 面孔四 · 自动化从未生效：站点一直显示的是你手动跑出来的产出
- **数据 / 数字**：真实事故 · 644 权限位 · 错位 1 天 · 标签全错
- **金句**：越像正常的故障，越要怀疑它根本没开始

---

## P2 · 根因 / 原理

- **标题**：为什么它们能这么安静
- **副标**：错误流去了你看不见的地方，观察位和发生位错开了
- **章节类型**：根因 / 原理
- **核心主张**：静默不是偶然，是「报错通道」和「干活通道」被设计成了两条路
- **认知锚点**：「错位的观察窗」—— 窗外是故障现场，屋里的人却背对着窗户
- **关键要点**：
  - 原理一 · 权限位：crond 直接 exec 脚本，不套一层 `sh`——没有执行位就报 Permission denied，而这个错只进系统日志，不进脚本自己的日志
  - 原理二 · 缺位顶替：数据源当天的接口没返回时，程序默默拿「最后一个有数据的日子」顶上，看起来有数据，其实日期错了
  - 原理三 · 算术截断：阈值写成整数除法，`19/28 = 67.9%` 被截断成 `0`，比较判断整个反向
- **数据 / 数字**：644 · 1 天 · 19/28 → 0
- **金句**：不是没出错，是错误去了另一间房

---

## P3 · 诊断 / 排除

- **标题**：先分清「没跑」和「跑歪了」
- **副标**：四步分诊，别在错的房间找钥匙
- **章节类型**：诊断 / 排除
- **核心主张**：所有静默故障只有两类——没执行、和执行了但结果不对——分诊错了，后面全是白工
- **认知锚点**：「四扇门」—— 一排各带一把锁的门，每把锁对应一种工具
- **关键要点**：
  - 第 1 步 · 查系统日志：`grep -i <脚本名> /var/log/cron`，找 `CMD (...)` / `CMDOUT (...)` 那一对，错误就在 CMDOUT 那行
  - 第 2 步 · 按 cron 的方式实跑：直接 `path/to/script.sh`，**不要** `sh path/to/script.sh`——后者会掩盖权限问题
  - 第 3 步 · 查日期锚点：问「序列的最后一格，锚定的是今天还是最后一个有数据的日子」
  - 第 4 步 · 查阈值算术：整数除法有没有被截断，改成交叉相乘
- **数据 / 数字**：4 步 · 2 类故障 · 1 次实跑
- **金句**：先确认它有没有跑，再问它跑得对不对

---

## P4 · 解法 / 操作

- **标题**：四条修复动作
- **副标**：补权限、锚今天、换算术、加保鲜
- **章节类型**：解法 / 操作
- **核心主张**：四条修复里，有三条的共同点是「让失败变得吵」
- **认知锚点**：「接上管子的四个接口」—— 四根断裂的管子重新对接，水第一次真正流动
- **关键要点**：
  - 修 1 · 权限：部署完立刻 `chmod 755`，并按 cron 的方式实跑一次；rsync -a 会保留权限位，但新建的目标文件不会自动带 +x
  - 修 2 · 锚定：序列最后一格显式锚到今天；用独立的当日权威源证明今天确实是交易日，再补空位；合并两个源要有明确优先级
  - 修 3 · 算术：阈值改交叉相乘 `NEW*10 < OLD*7`，不要写 `NEW/OLD*100`
  - 修 4 · 保鲜：新数据不足旧的 70% 或 items 为空时保留旧文件——半份数据不许覆盖好数据
- **数据 / 数字**：chmod 755 · NEW×10 < OLD×7 · 70%
- **金句**：半份数据覆盖好数据，是自动化最贵的一种手滑

## P5 · 进阶 / 纪律

- **标题**：三条铁律
- **副标**：把今天学费变成以后不再交的规矩
- **章节类型**：进阶 / 纪律
- **核心主张**：静默故障治不完，但可以做到「一次就根治」
- **认知锚点**：「三块基石」—— 三块石头稳稳托起一座写着「纪律」的塔
- **关键要点**：
  - 铁律一 · 脚本自己的日志干净 ≠ 任务跑过——cron 的执行记录在系统日志里，两边都要看
  - 铁律二 · 序列的最后一格必须显式锚定到「今天」，不能让「最后一个有数据的日子」默默顶替
  - 铁律三 · 兜底判据要能区分「今天没数据」和「今天不是交易日」——前者补空位，后者保持原样
- **数据 / 数字**：3 条铁律 · 2 种「今天」
- **金句**：沉默的地方留白，迟早会有人踩空

## P6 · 场景 / 迁移

- **标题**：同一个毛病的五个分身
- **副标**：CI 缓存、看板指标、爬虫、备份、增量同步
- **章节类型**：场景 / 迁移
- **核心主张**：换掉名词，这套排查法一字不改地照样成立
- **认知锚点**：「一只虫的五个分身」—— 同一只甲虫戴着五种帽子出现在五个场景里
- **关键要点**：
  - CI 缓存：缓存命中了旧依赖，看起来绿了，其实构建的是上一版
  - 看板指标：口径没变、数据源换了，天数对不上而总数看着正常
  - 爬虫任务：没报 403，但页面结构变了，解析出来全是空
  - 备份脚本：exit 0 写进日志，备份文件从来没落过盘
  - 增量同步：游标停在昨天，每天的增量都从同一起点开始
- **数据 / 数字**：5 个场景 · 1 套排查法
- **金句**：换个行业名，故障还是那张熟悉的嘴脸

---

## P7 · 收束 / 速查

- **标题**：速查卡：症状 → 查什么 → 怎么修
- **副标**：一格三栏，贴墙备查
- **章节类型**：收束 / 速查
- **核心主张**：把排查顺序固化成肌肉记忆，下次两分钟定位
- **认知锚点**：「口袋速查卡」—— 一张三栏卡片：左边症状，中间动作，右边结论
- **关键要点**：
  - 日志安静 → 查 `/var/log/cron` 的 CMDOUT → `chmod 755` + 按 cron 方式实跑
  - 数据停在昨天 → 查当日接口是否真的返回 → 显式锚定今天 + 独立源交叉验证
  - 数字对但逻辑错 → 查序列是否错位 → 末格锚今天，缺格用权威源补
  - 阈值不生效 → 查有没有整数除法 → 改交叉相乘
  - 一句话记住：**先看它跑没跑，再看它跑得对不对**
- **数据 / 数字**：4 行症状 · 4 个动作 · 1 条原则
- **金句**：问对问题，故障自己会举手
