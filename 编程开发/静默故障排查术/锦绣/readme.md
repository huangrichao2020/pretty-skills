## 公众号版（深度 · 1500-2000 字）

标题：**你的定时任务在跑，但它可能一次都没跑过**

你有没有遇到过这种情况：站点上的数据"停更"了，可你去翻脚本日志，里面干干净净，一条报错都没有。手动跑一遍，秒通。于是你以为是数据源抽风，重试、重试、再重试——直到某天你偶然看了一眼系统日志，才发现那个定时任务**从上线到今天，一次都没成功执行过**。

这类故障有个共同点：**它不报错**。报错会来找你，静默故障不会。它只是安静地替你把数据做旧，把标签算错，把自动化变成一个永远不触发的空壳。

### 一、四种面孔

**面孔一 · 脚本日志一片安静。** cron 每分钟都在触发，脚本日志里什么都没有。

**面孔二 · 数据停在昨天。** 抓取脚本没报错，页面上那个日期就是不动。

**面孔三 · 标签全错。** 每个数字单看都对，逻辑全错——连板序列整体错位了一天，而日志里什么异常都没有。

**面孔四 · 自动化从未生效。** 站点上一直在展示的，其实全是你某天手动跑出来的产出。

### 二、为什么它们能这么安静

答案很反直觉：**报错通道和干活通道，被设计成了两条路。**

**权限位那一条。** crond 执行脚本时是直接 exec，**不会**自动套一层 `sh`。所以脚本没有执行位（644），cron 每次都会报 `Permission denied`——但这个错误**只写进系统日志**（`/var/log/cron` 里的 `CMD (...)` / `CMDOUT (...)` 那一对），**不会**写进脚本自己的日志。于是脚本日志一片安静，看起来"什么都没发生"。

**缺位顶替那一条。** 数据源当天的接口偶尔拉不到时，程序如果去取"最后一个有数据的日子"来填，看起来是有数据、日期也还在，但它其实已经错了——整条序列错位一天，后面所有的标签全部跟着错，而日志里没有任何异常。

**算术截断那一条。** 阈值写成整数除法就完了：`19/28 = 67.9%` 在整数除法里变成 `0`，你以为在做 70% 的保鲜线，实际判断整个反了方向。

### 三、四步分诊：先分清"没跑"和"跑歪了"

所有静默故障只有两类——**没执行**，和**执行了但结果不对**。分诊错了，后面全是白工。

**第 1 步 · 查系统日志。** `grep -i <脚本名> /var/log/cron`，找 `CMD (...)` 和 `CMDOUT (...)` 那一对，错误就在 CMDOUT 那行。

**第 2 步 · 按 cron 的方式实跑。** 直接 `path/to/script.sh`，**不要** `sh path/to/script.sh`——后者会替你套一层 shell，**把权限问题掩盖掉**，让你误以为脚本没问题。

**第 3 步 · 查日期锚点。** 问一句：序列的最后一格，锚定的是"今天"，还是"最后一个有数据的日子"？

**第 4 步 · 查阈值算术。** 整数除法有没有被截断？改成交叉相乘。

### 四、四条修复动作

**修 1 · 权限。** 部署完立刻 `chmod 755`，并且**按 cron 的方式实跑一次**。注意 `rsync -a` 会保留权限位，但**新建**的目标文件不会自动带 +x。

**修 2 · 锚定。** 序列的最后一格必须显式锚到"今天"。要判断"今天没数据"还是"今天不是交易日"，需要一个**独立的当日权威源**来证明今天确实是交易日——有了它才补空位，没有它就保持原样。合并两个源时要有明确的优先级，别让两个源互相覆盖。

**修 3 · 算术。** 阈值改成交叉相乘：`NEW*10 < OLD*7`，不要写 `NEW/OLD*100`。

**修 4 · 保鲜。** 新数据不足旧的 70%，或者 `items` 为空，就保留旧文件。**半份数据不许覆盖好数据**——这是自动化里最贵的一种手滑。

### 五、三条铁律

1. **脚本自己的日志干净 ≠ 任务跑过。** cron 的执行记录在系统日志里，两边都要看。
2. **序列的最后一格必须显式锚定到"今天"**，不能让"最后一个有数据的日子"默默顶替。
3. **兜底判据要能区分"今天没数据"和"今天不是交易日"**——前者补空位，后者保持原样。

### 六、换掉名词，这套方法一字不改地成立

CI 缓存：缓存命中了旧依赖，看起来绿了，其实构建的是上一版。
看板指标：口径没变、数据源换了，天数对不上而总数看着正常。
爬虫任务：没报 403，但页面结构变了，解析出来全是空。
备份脚本：exit 0 写进日志，备份文件从来没落过盘。
增量同步：游标停在昨天，每天的增量都从同一起点开始。

**一句话记住：先看它跑没跑，再看它跑得对不对。**

## 小红书版（精简 · 350 字 + 8 张图）

**你的定时任务在跑，但它可能一次都没跑过。**

四种静默故障：
1. 脚本日志一片安静
2. 数据停在昨天
3. 标签全错，日志零报错

根因就一句话：**报错通道和干活通道是两条路。**
cron 不套 `sh`，脚本 644 → 每次报 Permission denied，但错只进 `/var/log/cron`，**不进脚本日志**。
