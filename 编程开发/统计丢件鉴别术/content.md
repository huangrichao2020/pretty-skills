## P0 · 封面 / 定位

- **标题**：统计丢件鉴别术
- **章节类型**：封面 / 定位
- **核心主张**：最贵的假干净不是"报错了"，是**统计结果少了一大半，而你完全看不出来**
- **认知锚点**：「漏了底的筛子」——筛子筛出来的东西看着很少很干净，其实漏了一半
- **关键要点**：
  - 症状不是"报错"，是**"结果少东西"**：问题数从 190 掉到 0、失败清单空了、统计条数少一半
  - 最贵的形态是**「0 条问题」**——它看起来是好消息，实际是统计工具自己瞎了
  - 危险在于**静默**：枚举命令退出码 0，不打一行警告，你只会拿到一个偏低的数字
  - 一句话口径：**统计结果先对账，再看内容**；期望产出数 ≠ 实际枚举数，就是丢件
- **数据 / 数字**：2 个丢失通道 · 3 步鉴别 · 4 个证
- **金句**：0 条问题，往往是 0 条被统计到

## P1 · 现象 / 痛点

- **标题**：统计结果少东西的三种面孔
- **章节类型**：现象 / 痛点
- **核心主张**：丢件有三个固定面孔，共同点是**没有一个会报错**
- **认知锚点**：「三条正在漏水的管子」——每一滴都漏了，而且都流得不声不响
- **关键要点**：
  - **面孔一 · 计数归零**：失败详情一条都解析不出来，bucket 全空 —— 看起来"全绿"，实际是枚举器瞎了
  - **面孔二 · 数量对不上**：期望 88 个 case，实际枚举到 0 个（或 40 个），清单悄悄少一截
  - **面孔三 · 样本不完整**：总数看着正常，但里面掺了不该有的样本 —— 比如把隐藏文件、临时文件也算进去
  - 它们的共性：**每一种都不抛异常，退出码都是 0**，日志干干净净
  - 为什么难发现：数据**变少**永远比数据**变多**更像一个好消息，而好消息没人会再去验一遍
- **数据 / 数字**：3 种面孔 · 0 次报错 · 0 次提醒
- **金句**：安静的统计最会骗人，因为它连报警都不屑于做

## P2 · 根因 / 原理

- **标题**：统计有两个互不相干的漏点
- **章节类型**：根因 / 原理
- **核心主张**：一次统计有**两个彼此独立的丢失通道**——产生端（管道截行）与枚举端（通配漏文件）；修掉一个，不代表另一个安全
- **认知锚点**：「两道各漏一点的筛网」——一道漏得少，一道漏得多，叠在一起照样漏
- **关键要点**：
  - **通道一 · 产生端**：`| tail -5` / `| head` / `grep -m` 在**数据流上**截断 —— 上一轮已修：改成全量落盘
  - **通道二 · 枚举端**：`glob` / `ls` / shell 通配在**收集文件时**就漏 —— 本轮踩的坑
  - **为什么上一轮的修法不够**：全量落盘解决的是"行会不会丢"，**根本没碰"文件会不会少"**——风险只是从一层挪到了另一层
  - **枚举端为什么会漏**：Python 的 `glob.glob('*.txt')` 按 POSIX 语义**不匹配前导点**（`.` 开头的名字被整体跳过）→ 目录里明明有 88 个文件，枚举器返回空列表
  - 最阴险的一层：**退出码是 0，一行警告都没有** —— 它不像是坏了，它像是"本来就没东西"
  - 通用判据：**任何要用来做统计的集合，都必须能说清"我是怎么枚举出来的"**
- **数据 / 数字**：2 个通道 · 88 → 0 · 1 次修复只挡住一半
- **金句**：全量落盘挡住了行，没挡住文件

## P3 · 破局 / 手法

- **标题**：期望数 vs 实际数，一行对账
- **章节类型**：破局 / 手法
- **核心主张**：鉴别丢件只需一个动作 —— **把"我期望统计到多少个"和"我实际枚举到多少个"摆在一起比**
- **认知锚点**：「两张收据对不上」——一张写着该有的数，一张写着实际收了多少
- **关键要点**：
  - **Step 1 · 先造期望数**：在跑统计**之前**就写下一个**独立来源**的期望数量（例如"上一轮记录了 88 个 manifest"）
  - **Step 2 · 同时记实际数**：统计跑完立刻打印**实际枚举到的样本数**——注意是"我数到几个样本"，不是"统计结果里有几条"
  - **Step 3 · 对账再解读**：两个数不等 → **先怀疑枚举器，再怀疑内容**；两个数相等 → 才轮得到看统计结果本身
  - **期望数必须独立**：不能拿"同一个 glob 的结果"当期望数 —— **那是同一把尺子量自己，永远相等**
  - 关键工程细节：`glob.glob('*.txt')` 不匹配前导点文件，`os.listdir` 不匹配，`find` 也不匹配 —— **枚举器本身要挑，而且最好一次上两把**
  - 现场：两把尺子量的目录完全相同，一个是 0，一个是 88 —— **差 88，就是全部**
- **数据 / 数字**：3 步 · 2 个数 · 1 个独立来源
- **金句**：先对收据，再看内容

## P4 · 陷阱 / 边界

- **标题**：漏了底的筛子
- **章节类型**：陷阱 / 边界
- **核心主张**：最贵的假干净是 **「0 条问题」**——它比任何报错都更像好消息，也比任何报错都更贵
- **认知锚点**：「漏了底的筛子」——筛得越干净，越要问一句东西去哪了
- **关键要点**：
  - 现场：`glob.glob('/tmp/3f_run/*.txt')` 返回**空列表**，而该目录里明明躺着 **88 个文件**（文件名以 `._` 开头，被当成隐藏文件整体跳过）
  - 后果一：解析器拿到 0 条 ❌ 详情 → 如果不核对，结论会被写成「**本轮 0 条失败原因**」
  - 后果二：这比"报告说有 53 条失败"更糟 —— **假绿比假红危险**，因为假红会让人去查，假绿让人去睡觉
  - 为什么难发现：**零结果不需要解释** —— 没有任何脚本会对"我没找到问题"发出警告
  - 现场被抓住的原因：另有一份独立记录写着 **88**，两个数一比就露馅了 —— **对账救的不是数据，是结论**
  - 通用判据：**任何"结果是 0 / 空 / 突然变少"的统计，先证明枚举器是好的，再相信这个 0**
- **数据 / 数字**：88 → 0 · 1 条差点写进历史的假结论 · 0 次报错
- **金句**：0 条问题，先证明你真能找到问题

## P5 · 零破坏 / 可逆

- **标题**：只读三件套
- **章节类型**：零破坏 / 可逆
- **核心主张**：鉴别丢件**全程只读** —— 三个动作，零次写操作，不碰被统计的对象
- **认知锚点**：「零破坏取样台」——台子上只有两支取样管，没有手术刀
- **关键要点**：
  - **动作一 · 全量落盘**：输出写进临时目录，**不经过会丢行的管道**（承接上一轮已确立的原则）
  - **动作二 · 双路枚举**：同一个目录用**两种枚举器**各数一遍（`glob` vs `os.listdir` / `find` vs `ls`），两数不等 = 有丢件
  - **动作三 · 对账留档**：把"本轮期望数 / 实际数 / 枚举口径"写进记录，让下一轮有尺子可对
  - 底线：**诊断丢件时不要改枚举命令去"试试看"** —— 改了就永远不知道原本漏了多少；正确做法是**另加一路对照**，不是在原路上打补丁
  - 临时产物放系统临时目录，**不写进被统计的目录**，避免自己制造新的口径漂移
  - 全程只读这条线**继承上一轮的结论**：鉴别阶段一次数据都不动
- **数据 / 数字**：3 个只读动作 · 2 路枚举 · 0 次写
- **金句**：诊断时只加对照，不改原路

## P6 · 验证 / 度量

- **标题**：一句"全绿"的四个证
- **章节类型**：验证 / 度量
- **核心主张**：想宣布"这轮没发现问题"，得同时拿出四个证，缺一个就下不了结论
- **认知锚点**：「四块拼图」——四块拼齐，图才成立
- **关键要点**：
  - **证一 · 期望数**：期望统计到的样本数，来自**独立来源**（上轮记录 / 上游清单）
  - **证二 · 实际数**：实际枚举到的样本数，来自**至少两个枚举器**
  - **证三 · 失败数非零**：真的跑出了 ❌ 详情行 —— **0 条失败在没有证一之前，只能读作"瞎了"**
  - **证四 · 逐桶对齐**：分类计数与上一轮**逐桶相同** → 判定"零回归"
  - 四个证的分工：证一证二对账"**有没有少**" · 证三证四对账"**算得对不对**" —— 前两个管样本完整性，后两个管计算正确性
  - 验收标准：**四个证齐了才能说"这轮没问题"**；缺任何一个，最多只能说"没发现异常"
- **数据 / 数字**：4 个证 · 2 类职责
- **金句**：先证明样本全，再证明算得对

## P7 · 收束 / 速查

- **标题**：五步落地卡
- **章节类型**：收束 / 速查
- **核心主张**：压成 5 行，每天巡检照着跑
- **认知锚点**：跳过 —— 纯清单，文字讲更清楚
- **关键要点**：
  - **Step 1 · 先记期望数**：来自独立来源，写下来（不要等跑完再想）
  - **Step 2 · 全量落盘**：输出不经会丢行的管道
  - **Step 3 · 双路枚举**：两种枚举器各数一遍
  - **Step 4 · 对账**：期望 vs 实际，不等就先查枚举器，再谈内容
  - **Step 5 · 逐桶对齐 + 留档**：把口径写进记录，让下一轮有尺子可对
  - 一条底线：**「结果是 0」在拿到证一之前，只能读作"统计工具瞎了"**
- **数据 / 数字**：5 步 · 4 个证 · 0 次破坏
- **金句**：先记账数，再看内容
