## P0 · 封面 / 定位

- **标题**：技能注入瘦身术
- **章节类型**：封面 / 定位
- **核心主张**：每轮对话开头都有一笔**与你今天说什么完全无关**的固定开销——而它常常占掉整轮的大头
- **认知锚点**：「一只每轮都被强行塞满的行李箱」——每次对话开场都要装一次，永远合不上盖
- **关键要点**：
  - 症状不是"慢"，是**账单**：不管你今天问什么，开头那一段固定内容一字不差地重复出现
  - 这笔固定开销由两块组成：**技能目录**（每轮注入的可用工具清单）+ **记忆全文**（Agent 自己的长期笔记）
  - 治理的难点不在"删"，在**"怎么删才不被运行时读回来"**——看着对、实则不生效的开关会让你白干一整晚
  - 一句话口径：**先量出每轮固定注入，再决定砍谁**；砍完要用**条目数**判断成败，不是字节数
- **数据 / 数字**：29,152 → 8,039 tokens/轮 · 省 72.4% · 8 页
- **金句**：你不是在为这次对话付费，你是在为那段永远重复的开场白付费

## P1 · 现象 / 痛点

- **标题**：一张永远长得一模一样的固定账单
- **章节类型**：现象 / 痛点
- **核心主张**：每轮对话的开头都有一笔固定开销，**它和你的任务无关，却要每轮都付**
- **认知锚点**：「一张每月都长一模一样的固定账单」——不管你今天说什么，第一行永远是同一笔开销
- **关键要点**：
  - 实测基线（优化前）：**每轮固定注入 29,152 tokens**，其中技能目录 **356 条**、记忆全文 **83,309 字节**
  - 更扎心的是**它大部分是废的**：356 条技能描述里，**348 条被预算截断到短于 20 个字符**——等于**没有描述**，有效描述占比只有 **2%**
  - 模型每轮都在读这份"几乎全是噪音"的清单：浪费的不只是 token，还有注意力——上百个半截描述会让工具选择变模糊
  - 记忆全文同理：83 KB 常驻，等于每轮都把整本笔记摊在桌上
  - 症状特征：**你以为自己在为"这一轮"付费，实际上大头是固定开销**——优化了半天提示词，账单却纹丝不动
- **数据 / 数字**：29,152 tok/轮 · 356 条技能 · 348 条描述被截断 · 有效描述 2% · 记忆 83,309 B
- **金句**：账单第一行永远写着同一句话

## P2 · 根因 / 原理

- **标题**：两个挂着「官方」牌子的死开关
- **章节类型**：根因 / 原理
- **核心主张**：找错开关是这条路上最大的时间黑洞——**两个被文档写着的字段，运行时根本不读**
- **认知锚点**：「两个挂着"官方"牌子的无效开关」——拨下去，灯不亮
- **关键要点**：
  - 死路一 · **`.ignore` 文件**：源码里确实有 `loadSkills` + ignore 包逻辑，看着完全对——但那是 **Pi 兼容层**代码，MCode 走的是 `externalSkillRoot` **另一条路径**，对外部技能根**不读 ignore 文件**
    - 实测证伪：**开/关两次真实会话，catalog 完全相同（360 条 / 17,364 B）**——一模一样，连字节数都没动
  - 死路二 · **`disable-model-invocation: true`**：文档表格里白纸黑字写着「skill is hidden from system prompt」——但 MCode 的 frontmatter 解析器**不读这个字段**，加了照样出现在目录里
  - 共同点：**文档 ≠ 实现**。字段写在文档里不代表运行时解析器读它；读代码时还要分清"兼容层代码"和"实际执行路径"
  - 真正的路径在运行时过滤链上：`filterInjectableRegistrySkills` → `.filter((entry) => entry.frontmatter.listed !== false)`
  - 一个省钱的方法论：**先花 10 分钟定位"运行时真正读的那一行"，再动手改**——否则你的所有"优化"都可能被运行时原样读回来
- **数据 / 数字**：2 个无效开关 · 360 条 / 17,364 B 两次实测完全一致 · 1 条真过滤链
- **金句**：文档不等于实现，兼容层不等于执行路径

## P3 · 破局 / 手法

- **标题**：唯一真正转动的那个开关
- **章节类型**：破局 / 手法
- **核心主张**：真正被读取的只有一个字段——**`listed: false`**，加一行就够
- **认知锚点**：「唯一能转动的那把钥匙」——锁孔里其余钥匙都是装饰
- **关键要点**：
  - 机制：在 SKILL.md 的 frontmatter 加 **`listed: false`** → 该技能从每轮注入的目录里消失，**但仍可用 `skill({name})` 按名加载**（隐藏 ≠ 卸载）
  - 单点验证（先别批量）：拿一个技能做实验 → 起一个**真实新会话** → 读它的 `systemPrompt` → 确认该条目消失、**对照项仍在**
    - 实测：`hta-agent-architecture-auditor-agent` 加了就从目录消失，`agent-reach` 作为对照项**依然在**——证明是"精准关掉这一条"，不是"整目录崩了"
  - 批量推进前先做**软链拓扑盘点**：`~/.agents/skills` 里多数条目是**软链**到 `~/dsh-skills` 或 `~/.claude/skills`，改软链会改到实体——必须用 `readlink` / `realpath` 找到真实文件再改
  - 官方来源优先：想知道某个技能有没有更近的入口，看它的 `source` 字段（`official` / `local`），别去翻 App 缓存目录
  - 收口口径：**该藏的藏起来，该留的留下来**——被藏的按需加载，留着的每轮必读
- **数据 / 数字**：1 行 frontmatter · 1 个单点实验 + 1 个对照项 · 215 个实体已标记
- **金句**：隐藏不是卸载，是让它不再每轮报到

## P4 · 陷阱 / 边界

- **标题**：越剪越胖的盒子
- **章节类型**：陷阱 / 边界
- **核心主张**：剪完之后 catalog 的**字节数不降反涨**——这不是失败，是预算机制在正常工作
- **认知锚点**：「一个拆掉砖块反而变大的盒子」——腾出的空间让剩下的砖块完整显示
- **关键要点**：
  - 实测反直觉结果：条目 **356 → 249（-107）**，但 catalog 块字节 **17,364 → 19,220（+1,856）**
  - 根因：catalog 有 **5,000 token 硬预算**（`min(contextWindow × 2%, 5000)`，**不可配**）；装不下就先截断描述、再装不下就省略整个条目
  - 所以剪掉 107 个条目腾出的预算，让**原本被截断到只剩几个字符的描述显示完整**——有效描述占比 **2% → 99%**
  - **指标陷阱**：拿字节数当成败指标，会得出"优化让文件变大了"的错误结论；**真正该看的是条目数 + 有效描述占比**
  - 同理别去调 `contextWindow`：2% × 512,000 = 10,240 > 5,000，早就顶到硬上限，**改 context 一分钱都省不到**
  - 记忆瘦身才是真省：把常驻只留"跨任务热规则"，专项实战迁到 topic 文件**按需加载**——**83,309 B → 11,270 B（-86%）**
- **数据 / 数字**：5,000 tok 硬预算 · 条目 356 → 249 · 字节 17,364 → 19,220 · 有效描述 2% → 99% · 记忆 -86%
- **金句**：别看字节数判断成败，看条目数和描述质量

## P5 · 零破坏 / 可逆

- **标题**：贴标签式改造
- **章节类型**：零破坏 / 可逆
- **核心主张**：全部改动**可逆**——只加一行、逐字节对账、留一键回滚
- **认知锚点**：「两百多份文件上各贴一枚不起眼的小标签」——每枚只有一行，正文一个字没动
- **关键要点**：
  - 不删正文：215 个技能**只加一行 frontmatter**，正文一字未删，仍可 `skill({name})` 按名加载
  - 记忆迁移要**逐字节对账**：46/46 条正文**逐字节命中**（83,057 B → 83,057 B，**差 0**）——差值必须为 0，差 1 字节都要查清
  - 合规池零误伤：19 个 knowhub 技能**迁到原生 user 根**（`~/.minimax/skills/`）再关外部根——先确认它们有替代来源，再动手
  - 三个备份先做：frontmatter 原文件、记忆原文、软链拓扑清单——**改之前全部落盘**
  - 一键回滚：写好 `ROLLBACK.sh`（恢复 frontmatter + 记忆 + 软链），并**实测跑一次**确认能退回去
  - 底线：**改动在下一个会话生效**，不要在同一轮里既改又验——验的是旧状态
- **数据 / 数字**：215 个技能只加 1 行 · 46/46 条逐字节差 0 · 19 个 knowhub 零误伤 · 1 个 ROLLBACK.sh
- **金句**：留错结论比不留更糟，留错配置比不改更贵

## P6 · 验证 / 度量

- **标题**：只认真实会话的验钞机
- **章节类型**：验证 / 度量
- **核心主张**：模拟器会骗你，**权威验证只能读真实会话的 systemPrompt**
- **认知锚点**：「一台只认真钞的验钞机」——模拟器过不了，只有真的会话才算数
- **关键要点**：
  - 权威口径：起一个**真实新会话** → 取它的 `llm-call.json` → 读 `systemPrompt` 字段 → 正则提 `<available_skills>` 块 → 数条目
  - **解析坑**：条目名要用 `^- ([^\s]+): ` 提取；用 `[^:]+` 会把 `lark:lark-approval` 这类**带前缀的名字截断**，导致计数虚高
  - 要同时量**三个数**，而不是一个：条目总数 · 描述短于 20 字符的条目数 · 记忆文件字节——单看任何一个都会得出片面结论
  - 最终账单（真实会话实测）：**每轮固定注入 29,152 → 8,039 tokens，省 21,113（-72.4%）**
  - 换算成体感：**100 轮会话省 211 万 tokens，1000 轮省 2,110 万**
  - 增量描述占比 **2% → 99%**（348 条 → 2 条）——这才是"省下来的注意力"的真实体现
- **数据 / 数字**：29,152 → 8,039 tok · 省 21,113（-72.4%）· 249 条目 · 99% 有效描述
- **金句**：模拟器说的不算，会话记录的才算

## P7 · 收束 / 速查

- **标题**：照着做，零破坏拿到七成
- **章节类型**：收束 / 速查
- **核心主张**：这套流程可以拆成 **5 步**，每步都有明确的验收标准
- **认知锚点**：「一张贴满正确操作的落地卡」——五格，每格都有可勾的验收项
- **关键要点**：
  - **Step 1 · 量**：起真实新会话读 `systemPrompt`，数条目 / 数截断描述 / 量记忆字节 → 记下基线（实测基线：29,152 tok · 356 条 · 83,309 B）
  - **Step 2 · 定位**：在运行时过滤链上找**真正被读取的那一行**（本例 `frontmatter.listed !== false`）；别信文档，别信兼容层
  - **Step 3 · 单点验证**：拿 1 个技能做实验 + 1 个对照项，起真实新会话确认——**只消失一条，不是整目录崩了**
  - **Step 4 · 批量 + 备份**：先备份（frontmatter / 记忆 / 软链拓扑），再改；记忆迁移**逐字节对账差 0**；合规池先迁到原生根
  - **Step 5 · 复验 + 回滚**：真实新会话复测三个数 → 写并实测 `ROLLBACK.sh` → **下个会话才生效**
  - 三个验收标准：**条目数降了** ✅ · **有效描述占比升了** ✅ · **记忆字节降了** ✅；字节数**不要求降**
  - 一条底线：**别拿模拟器当验收**——它跟你要治理的运行时不是同一套代码
- **数据 / 数字**：5 步 · 3 个验收标准 · -72.4% / 轮 · 21,113 tokens
- **金句**：先量、再定位、单点验、批量改、复验留退路
