- **定位**：微信 1-2 屏问答 · 数据可验证 · 不再是凭印象的「看起来对」。
- **配套升级**：v0.3.1 排版精修 + 微信输出三要求 + 禁止技术性元解释（08-20 三次反馈）。

## P1 · 真数据动态生成架构

- **核心主张**：emit_intraday_section 不再硬编码，直接读 `data['sector_leaders']` + `data['limit_up_stocks']` 真板块与真涨停股。
- **新增 collect_intraday_data()**：联动采集「板块涨幅 TOP + 涨停股 TOP + 板块资金 TOP」三件套。
- **新增 parse_sector_ranking**：解析 NeoData「板块涨跌排行 / 板块资金排行」markdown 表（行业 + 概念）。
- **新增 parse_limit_up_stocks**：解析「A 股个股交易排行榜」涨停 TOP N（默认 8）。
- **数据流**：NeoData 自然语言 → markdown 表 → 正则解析 → 真板块名/真涨停股 → 组装输出。
- **降级保护**：数据拉取失败 → 明说「数据缺失」+ westockdata 手动查的兜底，不瞎编。
- **认知锚点**：三条数据管道（板块/涨停/资金）汇成一个「可信结论」节点，管道分别标注 NeoData 三色，强调「动态」而非「写死」。

## P2 · 6 处关键 bug 修复

- **market_index**：抓到日期 `2026.0` → 重写 parse_index_table，正确取指数值与涨跌幅。
- **down_count**：显示 `5`（实际 5069）→ 用 `[\d,]+` + replace 修正则，正确解析下跌家数。
- **up_ratio**：显示 `0.76`（实际 0.08）→ 直接 parse 占比字段，不再被千分位误导。
- **sentiment_temp**：算成 `55`（冰点误判）→ 重写多因子算法，温度回归真实区间。
- **fund_flow_sectors**：返回 `[]` → split('|') 按列取，修复按省份而非按板块的错配。
- **场景识别错**：多日推演被错误分支吞掉 → 多日推演置顶优先识别。
- **认知锚点**：一个仪表盘上 6 个红灯依次变绿的修复清单，强调「数据可信度」是引擎的命脉。

## P3 · `\n` 字面量致命坑

- **核心主张**：NeoData 返回的是字面 `\n`（反斜杠 + n），不是真换行 chr(10)。
- **后果**：不处理 → 所有 markdown 表格按行分割失败 → 数据全空或错乱。
- **铁律**：所有解析器第一行必 `raw.replace("\\n", "\n")` 再分割。
- **覆盖位置**：parse_index_table / parse_sector_ranking / parse_limit_up_stocks / collect_intraday_data 全部前置。
- **教训**：接口返回格式 ≠ 标准换行，先验再解析，别 assume。
- **踩坑频率**：v0.2 就埋下，v0.4 仍在所有新解析器里保留这行（一票否决级）。
- **认知锚点**：一条被「反斜杠 n」卡住的解析流水线，旁边标红「先 replace 再 split」，强调这是一票否决级铁律。

## P4 · v0.3.1 排版精修

- **二级标题加冒号**：`❌ **一个危险**：`（不再用「主题 → 状态」）。
- **主题词不加粗、只加粗状态词**：`❶ 通信设备 → **要起飞**`（覆盖 v1.6.2）。
- **解读句独立成段**：每行 ≤40 字 + 空行分隔，不再挤压成一段。
- **上午/下午分段**：盘中机会场景支持 `上午：xxx` / `下午：xxx`。
- **灵活主题段**：无状态词也行，如 `❸ 光模块：xxx`。
- **末尾一句话独立成段**：`**一句话**：` 换行 + 短句动作清单。
- **认知锚点**：微信界面里一段红绿分明、带圆数字编号、末尾金标「一句话」的清爽短答，像聊天不像报告。

## P5 · 微信输出铁律

- **一屏原则**：禁止超过微信一屏（≥15-20 行就压缩，宁可删不要堆）。
- **不展示计算**：去掉「+30 亿 vs +2% = 资金抢筹」「5 日 -3.2%」罗列，只留结论。
- **个股 inline code**：`莱美药业` **+20%**（每只独立灰底小一号，必须带）。
- **小图标 ❶❷❸**：编号段必须用圆数字，不用阿拉伯 1.2.3.。
- **收尾声明**：末尾必加「非投资建议」。
- **认知锚点**：一个被压到「刚好一屏」的微信卡片，多余数据被剪刀剪掉，强调「少即是多」。

## P6 · 禁止技术性元解释 + 收束

- **核心主张**：直接给答案（结论 / 决策 / 操作），不要「工作日志」式元解释。
- **反例**：「skill 默认走了 XX 场景」/「重新拉最新真实数据」/「下面是一页纸…」。
- **元信息位置**：commit hash / 版本号 / 数据源放最后一行或脚注，不进正文。
- **风格标杆**：像 Reuters / Bloomberg 快讯那样清爽，不是「我现在去拉数据…」。
- **决策动作**：每个回答末尾给可照做的动作清单（买 / 持有 / 止盈 / 不参与）。
- **认知锚点**：一张「已处理」印章盖住啰嗦的工作日志，只露出干净的结论快讯，强调「用户要答案不要过程」。
