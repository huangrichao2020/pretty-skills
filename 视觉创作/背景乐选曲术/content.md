## P0 · 封面 / 定位

- **标题**：背景乐选曲术
- **章节类型**：封面 / 定位
- **核心主张**：配乐不是玄学。把「好听」拆成四个能测的数，选曲就变成排序题，混音就变成算术题
- **认知锚点**：「只剩低音的调音台」—— 一排推子全部滑到最左端，只有最低频亮着冷光，其余频段一片死寂
- **关键要点**：
  - 参考片里那首曲子**不属于任何人**，它是用 AI 现场生成的一次性产物 —— 所以你找不到「同一首」，只能找到「同一类」
  - 替代路线不是「找一首差不多的歌」，而是**先量出它的音色画像，再用画像去客观打分筛曲**
  - 全套流程可复跑：量参考片 → 打分选曲 → 造无缝 loop → 混音压底，每一步都留下可复算的数
  - 配套产物：7 个可复跑脚本 + 一套能直接接进任何短视频项目的 BGM 模块
- **数据 / 数字**：4 个画像指标 · 3 步造 loop · 1 套混音参数
- **金句**：找不到同一首，就找同一类

## P1 · 现象 / 痛点

- **标题**：配乐为什么这么难搞
- **章节类型**：现象 / 痛点
- **核心主张**：不是「找不到好曲子」，是**你没有判据** —— 耳朵只给结论，不给参数
- **认知锚点**：「贴着封条的曲库铁盒」—— 打开是空的，盒盖上只写着一行小字：要什么曲？没人答得上来
- **关键要点**：
  - 痛点一 · **没有自带曲库**：参考片的配乐是作者用 Suno 现场生成的，每支片子生成一次 → 世界上不存在「同一首」可以去找
  - 痛点二 · **AI 生成通路全灭**：MiniMax 音乐接口对新用户返回 2153「no longer available」· Suno 无 key 且 api.suno.com 本机不通 · Mureka 无 key · ChatCut 要账号 + 积分
  - 痛点三 · **选曲退化成玄学**：没有判据时，只能一首首试听、凭感觉选 —— 慢，且**说不出为什么选这首**
  - 痛点四 · **循环点一听就出戏**：随手截一段 30 秒铺底，结尾必然听出接缝，配乐瞬间从「氛围」变成「噪音」
  - 转机：把参考片的音色**量成数**，让「像不像」变成可排序的分数，让「循环」变成可验证的指标
- **数据 / 数字**：4 条生成通路全灭 · 1 个不存在的「同一首」 · 0 条判据
- **金句**：耳朵只会说「还行」，不会说「差 592 赫兹」

## P2 · 根因 / 原理

- **标题**：音色画像 · 四个能测的数
- **章节类型**：根因 / 原理
- **核心主张**：任何一首曲子都能被压成四个客观数字 —— 四个数定了，风格就定了
- **认知锚点**：「四把量声音的尺子」—— 四把刻度不同的金属尺并排压在一段声音波形上，各量各的那一段
- **关键要点**：
  - 指标一 · **节拍 BPM**：决定音乐的「步伐」。参考片三支片子全在 125–128 BPM，节奏是这首曲子的骨架
  - 指标二 · **响度 LUFS**：决定音乐的「音量人格」。参考片 integrated −12.8 LUFS、LRA 3.6 LU —— 响度平稳、动态收窄，是「垫底」而不是「主角」的响度
  - 指标三 · **谱质心（Hz）**：决定音乐的「明亮度」，即能量重心。参考片 592 Hz —— **极低**，意味着重低音铺底、中频极少
  - 指标四 · **频段能量分布**：五段占比（0–120 / 120–500 / 500–2k / 2–6k / 6–20k）。参考片 69% / 21% / 4.7% / 1.7% / 3.3% —— **七成能量压在最低频**
  - 关键推论：谱质心低 + 低频占比高 = **重低音铺底型 lo-fi**，这个画像对应的不是「某首歌」，而是一整类曲子的参数区间
  - 于是「找同一首」变成「找同一类」：只要 BPM 落在 ±4、谱质心落在同量级、低频占比 ≥ 60%，就是合格的替代曲
- **数据 / 数字**：4 指标 · BPM 125–128 · 谱质心 592 Hz · 低频 69% · −12.8 LUFS
- **金句**：曲子没有名字的时候，参数就是它的名字

## P3 · 方法一 · 量参考片

- **标题**：第一步 · 把参考片的音色画像量出来
- **章节类型**：核心解法 / 方法
- **核心主张**：不用凭感觉描述参考片，用工具把它的骨相量成一张**可复算的表**
- **认知锚点**：「一台频谱透视镜」—— 镜面里浮着声音的骨骼，镜外是安静的暗色房间
- **关键要点**：
  - 动作一 · **先验同源**：三支参考片（`cd6888ad…` / `11f3db7e…` / `a9f964c6…`）先做互相关 —— 谱图互相关 **0.84–0.89**、RMS 包络互相关 **0.44–0.60** → 判定为同一首曲子的不同段落
  - 动作二 · **量规格**：720×960 · 30fps · aac 48kHz 立体声 —— 先把输出规格对齐，再谈音色
  - 动作三 · **量四指标**：BPM 125–128 · integrated −12.8 LUFS / LRA 3.6 LU / true peak −2.3 dBFS · 谱质心 592 Hz · 频段 69/21/4.7/1.7/3.3%
  - 动作四 · **量动态**：每 2 秒 RMS 全程 0.10–0.20，末段掉到 0.059 → 音乐**连续垫满**，只有尾巴是收的
  - 输出物：一张画像表（4 个数 + 1 段动态描述）—— 它是后面所有步骤的**唯一判据来源**
- **数据 / 数字**：3 支片子 · 互相关 0.84–0.89 · 4 指标 · RMS 0.10–0.20
- **金句**：先给参考片称重，再去超市挑东西

## P4 · 方法二 · 客观打分选曲

- **标题**：第二步 · 拿画像去曲库里打分排序
- **章节类型**：核心解法 / 方法
- **核心主张**：有画像就有筛子 —— 把候选曲按同四个指标排序，**最接近的排在最前**
- **认知锚点**：「四把尺子夹着一排曲卡」—— 一排标着 BPM 与频段的卡片被四把尺子量过，长短不一的量尺长度一目了然
- **关键要点**：
  - 曲库来源选**机读**的：incompetech 的 `pieces.json` 有 **1443 首**，每首带 bpm / genre / feel / instruments —— 能被程序筛的，才是好曲库
  - 筛法：按参考片的谱质心 + 频段分布 + BPM 客观打分，取最接近的前若干首
  - 入选四首（与参考片逐项对表）：**Lobby Time** 129.2 BPM / 178 Hz / 73-24-2-0-0 · **Vibe Ace** 129.2 / 178 / 78-19-3-0-0 · **Inspired** 120.2 / 226 / 76-15-9-0-0 · **Airport Lounge** 129.2 / 196 / 64-34-2-0-0
  - 对照基准（参考片）：127.6 BPM / 592 Hz / 69-21-5-2-3 → 可以直接看出：入选曲的**频段分布几乎重合**，但谱质心差得远（178 Hz vs 592 Hz）
  - 这个差距**如实留着，不硬凑**：说明替代曲在「低频够重」上到位，在「整体更亮更窄」上有偏差 —— 知道偏差在哪，比假装一致有用
  - 每首都做成 8 小节对齐节拍的无缝 loop，128k 编码约 **118 KB**
- **数据 / 数字**：1443 首筛出 4 首 · 178 Hz 最接近 592 Hz · 每首 118 KB
- **金句**：筛选不是挑最好听的，是挑最像的那类

## P5 · 方法三 · 造无缝循环

- **标题**：第三步 · 把曲子做成真正无缝的 loop
- **章节类型**：核心解法 / 方法
- **核心主张**：无缝不是听出来的，是**切在拍点上 + 交叉淡化 + 幅度对齐**三件事一起做出来的
- **认知锚点**：「首尾相接的莫比乌斯环」—— 一条金属环带的两端真的连成一体，环上流动着连续的频谱光
- **关键要点**：
  - 步骤一 · **分离**：用 demucs 抽 no_vocals 轨（`--two-stems=vocals`）—— 122 秒音频在 M2 Pro CPU 上只跑 **9 秒**
  - 步骤二 · **切在拍点**：128.4 BPM → 1 小节 = **1.869 s**；在 RMS 变异系数 < 0.20 的稳定区（70–92 s）取整 **12 小节 = 22.43 s**
  - 步骤三 · **等长交叉淡化**：尾部 2 s 与头部做等长交叉淡化 → 接缝不在任何一个小节头上，耳朵抓不到
  - 步骤四 · **幅度归一**：RMS 归一到 **0.113** + 软限幅（tanh，peak 0.856）—— 循环点和曲内其他位置的响度必须一致，否则会「咯噔」
  - **怎么验证无缝（别靠听）**：看循环点一阶差分 —— 实测接缝处最大 **0.0102**，全曲平均 **0.0107** → 接缝不比别处更突 → 无缝成立
  - 这套切法**四首候选曲通用**：同一套节拍网格切 8 小节，一份代码批量产出
- **数据 / 数字**：128.4 BPM → 1.869 s/小节 · 12 小节 22.43 s · 接缝 0.0102 vs 均值 0.0107
- **金句**：无缝是一个能算出来的数，不是一个能听出来的感觉

## P6 · 坑与纪律

- **标题**：三个真踩过的坑
- **章节类型**：深化 / 避坑
- **核心主张**：这套流程里真正会翻车的地方，不在算法，在**数据来源、代理与版权**
- **认知锚点**：「三块绊脚的石头」—— 三块形状各异的暗色石块横在一条明亮的管线上，每块上都刻着一行小字
- **关键要点**：
  - 坑一 · **分离不等于干净**：原片 vocals 轨有 **27 段人声**，分离后 no_vocals 轨仍剩 **5 段残留** → 会听出「掏空感」
    - 破法：先验证参考区间本身有没有人声 —— 70–95.5 s 段 vocals 轨能量只占 **1.8%**，说明这曲子本来是纯器乐，抠出来的 loop 不会有掏空感
  - 坑二 · **代理会截断大文件**：`pieces.json` 这类大文件会被中途掐断 → 必须走 **Range 分块下载**
  - 坑三 · **版权不能含糊**：从朋友视频里分离出的 `ref_bgm_loop.mp3` **仅限自用 / 内部测试**；公开发布前必须换成原创或授权音乐
    - 纪律：曲库每首都配同名 `.json` 记作者 / 许可证 / 来源，CC BY 4.0 公开发布需署名 `Music: <title> by Kevin MacLeod (incompetech.com) - CC BY 4.0`
  - 附加纪律 · **别把接口当能力**：MiniMax 音乐接口对新用户直接 2153「no longer available」—— **接口存在 ≠ 你能用**，可用性要当天实测，不靠文档
- **数据 / 数字**：27 段人声 → 5 段残留 · 1.8% · 2153 错误码 · 1 条署名要求
- **金句**：能跑通是运气，能署上名才是本事

## P7 · 收束 / 速查

- **标题**：速查卡 · 从参考片到成片
- **章节类型**：收束 / 速查
- **核心主张**：六步跑完，每一步的产物都是下一步的输入 —— 整条链可复算、可交接、可外包
- **认知锚点**：「一张口袋速查卡」—— 卡片左列六道工序，中列每步的产出，右列每步的验收数
- **关键要点**：
  - ① 量参考片 → **产出**：4 指标画像表（BPM / LUFS / 谱质心 / 频段）+ 动态描述
  - ② 建机读曲库 → **产出**：可程序筛的候选表（如 incompetech 1443 首 `pieces.json`）
  - ③ 客观打分 → **产出**：排序后的替代曲清单 + 逐项对照表（含**如实标出的偏差**）
  - ④ 分离 + 切拍点 + 交叉淡化 + 幅度归一 → **产出**：无缝 loop（验收：一阶差分 ≤ 全曲均值）
  - ⑤ 配同名 `.json`（作者 / 许可证 / 来源）→ **产出**：可发布的曲库（署名信息随曲走）
  - ⑥ 混音压底 → **产出**：成片（**−20 dB · 淡入 1 s · 淡出 2.5 s** —— 官方做法就这三个数）
  - 一句话记住：**先把参考片量成数，再让数字替你选曲**
- **数据 / 数字**：6 步 · 3 个混音参数 · 1 条验收线（一阶差分 ≤ 均值）
- **金句**：配乐的手感，藏在这四个数里
