# 口播分段动效工作台 · 四环节闭环 + 卡片库 + 偏好表复利

> 3F Content 范式 · F1 源文字版 · 人只做判断 · AI 只做执行 · 质量期期复利

---

## P0 · 封面 / 定位

- **标题**：口播分段动效工作台
- **副标**：四环节闭环 + 卡片库 + 偏好表复利
- **章节类型**：封面
- **核心主张**：口播视频的动效不该由 AI 每次重新抽一次 —— 审美应该搬进代码，AI 只做语义判断
- **认知锚点**：「4 环节 · 3 闸门 · 9 卡 · 4 载体」
- **关键要点**：
  - 四环节：对话策划 → 分段动效 → 人工审核 → 配口播出片
  - 三道闸门：结构（人判）→ 机器（lint error=0）→ 审美（人判）
  - 卡片库：9 张卡 × 9 用途组，双维度分类（用途 / 视觉标签）
  - 复利四载体：卡片库 · 偏好表 · lint 阈值 · STATUS
- **数据 / 数字**：9 张卡 / 16 个 MCP 工具 / 4 环节 / 3 闸门 / 渲染 7–9 秒每段
- **金句**：改一个效果要翻三个文件，就没法参数化，没法检查，每期从零开始 —— 那不是工作流，是手工作坊

## P1 · 问题：为什么直接让 AI 出整片不管用

- **章节类型**：问题
- **核心主张**：整片生成的失败不是模型不够聪明，是架构让「改」变成了「重抽」
- **认知锚点**：「重新抽一次」
- **关键要点**：
  - 直接让 AI 出整片成片，人只能在「全盘接受」和「全盘重来」之间选
  - overlay-studio 的原话：「说改个颜色，它把布局也动了；改一次，等十分钟」
  - 根因：审美在 prompt 里 → 每期重新抽 → 风格漂移
  - 拆段之后：人一次只判断 5 秒，改一次的代价降到 1/N
- **数据 / 数字**：判断成本 1/N，迭代代价 1/N
- **金句**：不是模型不够聪明，是让它每次都重新想一遍

---

## P2 · 解法一：四环节闭环 + 三道闸门

- **章节类型**：解法
- **核心主张**：把「生成」拆成四段，每段之间放一道能被机器或人判定的闸门
- **认知锚点**：「结构 → 机器 → 审美」
- **关键要点**：
  - ① 对话策划：人想内容，AI 排结构（时长按口播 4.5–5 字/秒推，不拍脑袋）
  - ② 分段动效：AI 选卡排参数渲 mp4，lint error 必须为 0
  - ③ 人工审核：人只答三问 —— 看懂了吗 / 想看吗 / 配得上吗
  - ④ 配口播出片：人录口播 → 切句 → 贴右上角 → 合成
  - **分工铁律**：人只做判断，AI 只做执行。审美判断是唯一必须留给人的环节
- **数据 / 数字**：4 环节 / 3 闸门 / 状态机 5 态（draft→rendered→approved→voiced→locked）
- **金句**：机器判得了「时间越界」，判不了「这段有点闷」

---

## P3 · 解法二：卡片库 —— 审美搬进代码

- **章节类型**：解法
- **核心主张**：一张卡 = 一个模板 + 一组参数 + 一条用途说明；改一张卡，全片受益
- **认知锚点**：「卡片库是复利的第一载体」
- **关键要点**：
  - 9 张卡分 9 个用途组（钩子/证据/数据/对比/金句/步骤/过程/标注/常驻）
  - 双维度分类：group（干什么用）互斥 + tags（看起来怎么动）可多选
  - 通用旋钮 5 个（accent/offsetX/offsetY/scale/speed）+ 每卡专属参数
  - 一段一主卡；连续两段不同形态（否则是 PPT 感）
  - 图形优先，纯文字卡是最后选择
- **数据 / 数字**：9 卡 / 9 组 / 9 视觉标签 / 5 通用旋钮
- **金句**：把审美从 prompt 搬进代码，风格就不再漂移 —— 改一处，全片受益，而且零 token

---

## P4 · 解法三：复利四载体 + 「学一下」闭环

- **章节类型**：解法
- **核心主张**：没有复利，上面全是「一次性好用」；这一期省下的时间要超过前几期攒下的总量
- **认知锚点**：「一次是手滑，两次才是偏好」
- **关键要点**：
  - 载体一：卡片库（攒卡，新形态加一张，全片受益）
  - 载体二：偏好表（唯一取值源：出厂默认 < 经验规则 < 用户偏好 < 本段 params）
  - 载体三：lint 阈值（越审越准：噪音越少，剩下的 warn 越值得看）
  - 载体四：STATUS.md（接力状态：到哪一步、哪些定稿、踩了什么坑）
  - **学一下闭环**：人改参数 → 系统记录 → 出现 ≥2 次的倾向 → 写成规则 → 下期直接按这个排
  - **lint 只报告不改写**：lintOff 是用户的主动决定，重排必须原样保留
- **数据 / 数字**：4 载体 / ≥2 次阈值 / 单行 ≤12 字 / 驻留 ≥2 秒
- **金句**：口喷一次没用，改完再让 AI 学，两次以上才写成规则

## P5 · 落地：任意 agent 都能接管

- **章节类型**：落地
- **核心主张**：项目零 AI 逻辑，但能力必须机器可读 —— 散文会过期，契约不会
- **认知锚点**：「装上就能用，不读散文」
- **关键要点**：
  - 三层同源：MCP（agent）· CLI（人/脚本）· HTTP（工作台），底层同一套，不存在第二套真相源
  - MCP 16 个工具，每个都有 description + inputSchema
  - 契约从代码生成（registry → 卡片，shots → 状态机，lint → 规则，prefs → 默认值）
  - 接手自检一条命令：跑完知道项目健不健康，不必先读三份文档
  - 迭代成本：改卡片库 → 所有 agent 立刻受益
- **数据 / 数字**：16 工具 / 3 层接入 / 1 条自检命令
- **金句**：让任意 agent 快速接管，落地成一件具体的事就是 —— 它跑一条命令就知道能不能用

## 附：实战记录

- **项目**：vlog-film（本地工作台，纯执行器）
- **验证**：9 张卡全部渲染 + 抽帧验收 + 4 段端到端成片 + MCP 全链路实测 + 「学一下」闭环实测
- **实战抓出的 bug**（都是「看着正常其实不对」）：
  - terminal-run 的行分隔符不认 `|` → 4 条过程行挤成 2 行长句
  - contrast-vs 左侧条目 div 是空的 → 文案一个字都没渲染出来
  - quote-punch 没有 PREPARE 钩子 → 用户按惯例写的 `|` 显示成字面量
  - lint 按原始字符串长度算字数 → 把高亮分隔符算进去，误报一片
  - 「学一下」按卡类型分桶 → 通用参数（accent）跨卡偏好被拆成 N 份，够不上两次
- **教训**：**渲染成功 ≠ 渲染正确。** 每张卡都要抽帧看图；每个 bug 都是「代码跑通了但结果是错的」
