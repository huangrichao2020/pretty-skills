# 口播分段动效 · 四环节工作流

## 一句话定位

```
人想清楚要说什么 → Mavis 排成分镜表 → 每段渲成动画 → 人逐段点头/打回 → 配口播出片
       ↑                                                          │
       └────────────── 卡片库 + 偏好表 + lint 复利 ───────────────┘
```

**为什么是这个结构**：直接让 AI 出整片成片，人只能在「全盘接受」和「全盘重来」之间选。
拆成段之后，人一次只判断 5 秒 —— 判断成本降到 1/N，改一次的代价也降到 1/N。

**谁做什么**（这条是整套方法的地基，别搞反）：

| 谁 | 做什么 | 绝不做什么 |
|---|---|---|
| **人** | 想内容、给判断、点头或打回 | 不碰 HTML、不碰参数 |
| **Mavis** | 排分镜、选卡片、写文案、渲、合成 | 不替人做审美决定 |

**项目本身不接任何 AI。** 所有生成决策在 Mavis 那边，项目只负责渲染/审核/合成。
这条不是洁癖 —— 项目一接 AI，生成成本和不确定性就回来了。

---

## 四个环节

| # | 环节 | 谁主导 | 产出 | 闸门 |
|---|---|---|---|---|
| ① | **对话策划** | 人想 + Mavis 排 | 分镜表（段序 / beat / 口播稿 / 时长） | 人认可结构 |
| ② | **分段动效** | Mavis 排版 | 每段一个 mp4 | lint error = 0 |
| ③ | **人工审核** | 人判断 | 每段 approved / 打回 | 人点头 |
| ④ | **配口播出片** | 人录 + Mavis 合成 | 成片 | 人工看过 |

**闸门是硬的**：没过闸不往下走。
② 的闸门是机器判（lint error 必须为 0），③ 的闸门是**人**判（AI 不能替）。

## 环节① 对话策划 → 分镜表

### 怎么跟人聊

**先问清一件事**：这条视频要人记住什么？记不住就白做。
不要一上来就问「想要什么风格」—— 人回答不了这个问题，只会给你一个假答案。

问法（一次问一个，别列清单）：
- 「这条讲完，你希望观众记住哪一句？」
- 「有没有一个反常识的点？哪怕很小。」
- 「你手上有什么真数据？数字必须是真的。」

### 排分镜表

**段 = 一句话说完的一个论点**，不是 PPT 页。
每段一个 beat（一句话概括这段讲什么）、一句口播稿、一个时长。

**节奏参考**（短视频爆品的通用结构）：

| 位置 | 时长 | 干什么 |
|---|---|---|
| 钩子 | 0–3s | 一句反常识的话，把人按住 |
| 立论 | 3–10s | 说清问题 |
| 证据 | 10–25s | 给真数据 / 真过程 |
| 转折 | 25–40s | 「但是」—— 这里决定别人看不看下去 |
| 收 | 40s+ | 落一句能被截图的话 |

**一段一件事。** 一段塞两个论点，两个都记不住。

**时长从口播稿长度推**，不要拍脑袋：
中文口播约 **4.5–5 字/秒**（带停顿更慢）。
一句 20 字 → 约 4.5 秒。写完稿子按这个算，别用默认值。

### 工具

```bash
python3 workbench/shot.py new --title "标题" --slug <slug>
python3 workbench/shot.py add --slug <slug> --beat "钩子" \
        --narration "你以为难的是剪，其实难的是决定剪哪一段。" --duration 4.5
```

## 环节② 分段动效 → 卡片编排

### 核心原则：选卡片，不写 HTML

**卡片库**是复利的第一载体：一张卡 = 一个模板 + 一组参数 + 一条用途说明。
改一个效果只改一张卡，全片受益；每期从零开始写 HTML 叫**不复利**。

```bash
python3 workbench/shot.py cards        # 列卡片库（按用途分组）
```

### 卡片库（9 张，9 个用途组）

| 用途组 | 卡片 | 什么时候用 |
|---|---|---|
| 钩子开场 | `hook-line` 大字钩子 | 开篇 3 秒，一句反常识的话，2-3 行大字 |
| 证据实证 | `number-proof` 数字实证 | 抛硬数据。**数字必须是真的** |
| 数据指标 | `growth-curve` 曲线生长 | 讲趋势。**假曲线一眼假** |
| 对比取舍 | `contrast-vs` 撕裂对比 | 「A 还是 B」「以前 vs 现在」。一次只对比两个 |
| 金句观点 | `quote-punch` 金句重击 | 一句要被截图转发的话。说完就撤，别解释 |
| 步骤流程 | `step-stack` 步骤栈 | 讲流程。**超过 5 步拆两段** |
| 过程展示 | `terminal-run` 过程终端 | 讲「我是怎么做的」，像正在干活 |
| 教程标注 | `timeline-mark` 时间轴标注 | 指认「这一段是关键」 |
| 常驻层 | `chapter-bar` 章节条 | 全程在场的顶部导航条 |

**选卡规则**：
1. **一段一主卡**。段内最多一张标志性主卡。
2. **连续两段不许同形态** —— 这是「PPT 感」的直接来源，lint 的 `repeat-kind` 会报。
3. **图形优先，纯文字卡是最后选择**。先用数字、对比、过程，再用文字。
4. **别用钩子卡做正文** —— 钩子的价值在于「一句话就够」，当正文用就废了。

### 排卡

```bash
python3 workbench/shot.py card --slug <slug> --id s01 --kind hook-line \
        --start 0.2 --end 4.5 \
        --set "kicker=剪片的真相" \
        --set "lines=你以为难的是剪|其实难的是决定剪哪一段"
```

参数值里的 `|` 是**高亮分隔符**：`前段|后段` → 后段被高亮成强调色。

**时间怎么定**：
- `--start` 建议 ≥ 0.2s（别一上来就闪）
- `--end` ≤ 段时长（超了 lint 报 `time-overflow`）
- 驻留 ≥ 2s（`min-dwell`），观众来不及看清

### 文案硬约束

**单行 ≤ 12 字**（lint 的 `maxLineChars`）。超了会顶出画面 —— 这是真问题，不是 lint 吹毛求疵。
标题 ≤ 8 字，条目 ≤ 11 字（字号更大，能放的字更少）。

### 渲染

```bash
python3 workbench/shot.py render --slug <slug> --all
```

**耗时**：约 7–9 秒/段（Chrome 冷启动 4 秒 + 每段 7.4 秒）。
渲染是逐帧 seek，**必须用 CSS animation，transition 不被捕获**。

### 体检（② 的闸门）

```bash
python3 workbench/shot.py lint --slug <slug>
```

**只报告，永不改写。** 分两级：
- **error** —— 硬伤，必须修完（占位文案、时间越界、时间倒序）
- **warn** —— 编排规律，人判优先（驻留太短、空白过长、同屏重叠、同形态连续、缺常驻层、文案过长）

**lintOff 是用户的主动决定**，改完重排必须原样保留 —— 严禁把用户的决定「修复」成规则认可的样子。

## 环节③ 人工审核 → 点头或打回

打开 **http://127.0.0.1:8787/** —— 首页就是审核台。

每段一张卡：封面 / 段号 / beat / 口播稿 / 状态 / 时长 / 口播绑定。
可以 ▶ 播、✓ 这段可以、↺ 要改。

### 人只回答三个问题

1. **这段看懂了吗？**（信息够不够）
2. **这段想看吗？**（形态对不对）
3. **这段配这句口播对得上吗？**（音画对不对）

**AI 不替人判断。** 打回的时候，尽量说清「哪里不对」——
「不好看」没法复用，「文案太长顶出画面」才能变成规则。

### 状态机

```
draft ──> rendered ──> approved ──> voiced ──> locked
  ↑           │            │            │
  └───────────┴────────────┴────────────┘   （打回重渲）
```

非法跳转会被拒绝。

## 环节④ 配口播出片

### 人录口播

真人出镜（或录屏），一段一条音频/视频。
**录的时候就按段录** —— 一段一条，对齐简单得多。

### 贴片

```bash
python3 workbench/shot.py voice --slug <slug> --id s01 \
        --file /path/口播.mp4 --start 0 --end 4.2
```

口播贴到**右上角**，圆角 + 底边羽化。位置由 `--pip-x/--pip-y/--pip-w/--pip-h` 决定：
`(822, 138)` 起，`228×255`。

**画面的右上角必须留空** —— 动画内容不许进这个矩形，否则会盖住人脸。

### 合成

```bash
python3 workbench/shot.py compose --slug <slug>
```

## 复利：怎么让下一期更好

这是整套方法**最重要**的部分。没有它，上面四环节只是「一次性好用」。

### 三个载体

| 载体 | 文件 | 管什么 | 复利方式 |
|---|---|---|---|
| **卡片库** | `workbench/cards/` | 有哪些画面形态 | 攒卡 —— 每期遇到新形态就加一张，全片受益 |
| **偏好表** | `workbench/prefs/我的偏好.md` | 这个人的审美取值 | 学一下 —— 从改动里长出规则 |
| **lint 阈值** | `workbench/lint-rules.local.json` | 什么算问题 | 越审越准 —— 噪音越少，剩下的 warn 越值得看 |

**偏好表是唯一取值源**。参数优先级：
```
卡片库出厂默认  <  经验规则  <  用户偏好  <  这一段显式设的 params
```

### 「学一下」闭环

```
① 按当前偏好排一期
② 人在工作台里改参数（改什么都记下来了）
③ 说一句「学一下」
④ 出现 ≥2 次的倾向 → 写成规则 → 下期直接按这个排
```

**为什么必须 ≥2 次**：一次改动是手滑，两次才是偏好。
只出现一次就写进规则，等于把用户的临时决定固化成下期的默认。

```bash
python3 workbench/shot.py learn --slug <slug>              # 看倾向（只报告）
python3 workbench/shot.py learn --slug <slug> --write      # 用户确认后才写
```

**注意**：`--write` 只能在**用户明确确认之后**用。
AI 不擅自固化审美 —— 这是整套机制能长期有效的前提。

### 沉淀到下一棒

```bash
python3 workbench/shot.py status-file --note "渲完 s01-s03，s02 文案溢出待改"
```

`workbench/prefs/STATUS.md` 记录：现在到哪一步、哪些定稿了、踩了什么坑。
**换人 / 隔几天回来 / 换台机器，先读这个。**

## 硬约束清单（违反就出问题）

| 约束 | 值 | 违反的症状 |
|---|---|---|
| 画布尺寸 | 1080×1440 | 元素位置全错 |
| 右上角留空 | `(822,138)` 起 `228×255` | 盖住人脸 |
| 动效形式 | 一律 CSS `animation` | 画面静止（transition 不被逐帧 seek 捕获） |
| 渲染器 | 模块级 Chrome 单例 | 同线程嵌套开第二个 playwright **会死锁** |
| 文案长度 | 单行 ≤ 12 字 | 顶出画面 |
| 停留时长 | ≥ 2s | 观众来不及看清 |
| 口播位坐标 | 用 `PIP_W`/`PIP_H` | 把 `(x0,y0,x1,y1)` 当宽高用 |
| ffmpeg overlay | **第一个参数是主画面** | 尺寸不匹配报错 |
| 动画段音轨 | 先 `ffprobe` 判断 | 写死 `[0:a]` 报错 |

## 怎么接进来（任意 agent）

**三条路径，底层是同一套**（不存在第二套真相源）：

| 路径 | 给谁 | 怎么接 |
|---|---|---|
| **MCP** | agent（推荐） | 配 `workbench/mcp_server.py`，16 个工具自动暴露 |
| **CLI** | 人 / 脚本 | `python3 workbench/shot.py <cmd>` |
| **HTTP** | 工作台网页 | `http://127.0.0.1:8787` |

### 开工前先跑这条

```bash
python3 workbench/tools/check_contract.py --verbose
```

全绿 = 项目可以接手。有 error 就先修，别开始。

### 不要读散文，先读契约

```bash
python3 workbench/contract.py           # 完整机器可读契约
python3 workbench/contract.py --cards   # 卡片库 + 全部参数（类型/范围/枚举）
```

**契约从代码生成，不会过期。** 参数名以它为准，不要猜。

### agent 的三条硬规矩

1. **不跳闸门** —— G1/G3/G4 是人的决定
2. **不猜参数名** —— 先 `capability_contract` / `list_cards`
3. **不擅自写偏好表** —— `learn --write` 只能在用户确认之后

### 第四条：数据只有一份，改完就生效

agent 用 CLI 改分镜表 → 人在工作台刷新就能看到；人改完参数 → agent 下一次
`shot.py list` 就能读到。**中间不需要任何同步动作。**

⚠️ 如果发现「两边结果不一样」「一边改了另一边没反应」——
**先怀疑自己读的不是同一份数据**（仓库 / 运行副本各存了一份），
别急着查代码逻辑。数据路径一旦按「代码在哪」推导，两份代码就必然分叉。

完整接入文档见 `docs/INTEGRATION.md`。

## 什么时候不该用这个

- **纯图片/静态图文** —— 不用动效，直接排版更快
- **旁白无真人出镜** —— 右上角留空就没意义了，参数面板那套也可以简化
- **一次性的视频** —— 建库和写偏好表是前期成本，单发不值得
